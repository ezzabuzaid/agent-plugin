## 2. Take the scope and the name from the standard libraries

## 3. Put the API on paper and get it reviewed

**The leaders decide.** _"I need to do what is proper man"_ and _"it is not about preference you know"_ (2026-10-06). An idea that no leader ships is dropped; use your own judgment only where no leader covers the case, and say that it is yours. `experiments-mutex/decide-correct-design-not-preference.md`

**Defend the recommendation; a question is not a ruling.** _"my decisions are not affirmative"_ (2026-10-22), after an agent swung twice in two turns on a remark. _"I trust your recommendation, and I want you to be very bold about them and defend them to the core"_ (2026-11-07). _"Bro, I trust your recommendation. The port kept Codex's config name, default, cap rule and verbatim error strings, and dropped Codex's legacy alias. For the SQLite queue: _"we are supposed to match pg boss interface, which already have on error, why is that not happening?"_ (2026-10-02). **Design the package, not today's apps.** _"please design this without caring about the apps today. this is package that would be moved from here later on and be published."_ (2026-10-02). **Callers are evidence, never the source of an API.** _"the consumer must be obliged to follow the package not the other way around."_ (2026-10-25), after a CLI choice changed how the pool was built. _"remember we follow Martin Fowler. We don't design for the current consumer. We force the consumer into the proper behavior."_ (2026-11-06), after an agent fitted a watcher to its 24 callers. **A runtime validation error is an illegal state the types let through.** _"this design doesn't align with not representing an illegal state also it is backward compatibility which is prohibited"_ (2026-10-30). ConflictingAnswerError, NoEvidenceError and a duplicate-id RangeError each marked such a state. In the approved shape each scorer takes only the inputs it reads. `experiments-context-compiler/runtime-errors-mark-illegal-states.md`

**A package owns its errors, with a class for each next step.** _"now and be ruthless about breaking changes. we should drive the host not otherwise"_ (2026-10-28). `new DataVersion(path, MessagesUnavailableError)` took a host's error class; the host now translates at its own boundary. _"I prefer naunced error classes for cases where an error expcetion actually make a differnce."_ (2026-10-20): a class exists only where `instanceof` changes what the caller does. `experiments-mutex/packages-own-their-errors.md`, `experiments-mutex/nuanced-error-classes.md`

**The clock, the environment and paths are inputs.** _"clock as an input"_ (2026-11-02). Every caller passes the clock, with no default: an app entry gives `globalThis`, a test gives sinon's `createClock()`. A port stays aligned with its upstream: sqlite-queue's clock stays optional, as in pg-boss (_"[...] we need to stay aligned to pg boss"_). For the environment: _"concurrency should not be forbidden instead should be encouraged. we need to remove this class and scream at any test cases that overrides env. we need to fix things from ground up."_ (2026-10-26). For shared state: _"no module levels or singletons. at all. this is absolutly wrong."_ (2026-07-25); a package exports mechanism, never instances. `experiments-mutex/time-primitives-standard.md`, `experiments-mutex/tests-never-override-env.md`, `January-text2sql/feedback-no-module-state-or-singletons.md`

**Decoupled OOP with named patterns.** _"make sure to decouple the functionality. we want to use proper design pattern oop. also folder structure should tell what we are looking at."_ _"I don't really like god functions. I like composed composable … I meant OOD"_ (2026-11-03). _"why functions listen and connect instead of them being part of class ... I am just not fan of lone functions like this"_ (2026-11-14): a result that owns a resource over time is a class with `[Symbol.asyncDispose]`, as in .NET `System.IO.Pipes`. `experiments-mutex/design-rules.md`

## 5. Scaffold from the newest package of the same kind

**Copy the sibling's files whole.** _"create tsconfig.spec.json and update tsconfig.lib.json to be like the others"_. Hand-rolled configs also caused a TS6305 composite-build error that the sibling shape avoids. A new stdlib primitive in text2sql clones a sibling's package.json, project.json, tsconfig files, vite and eslint configs. `January-text2sql/feedback_mirror_sibling_configs.md`, `January-text2sql/feedback_new_primitive_own_stdlib_package.md`

**The newest package of the same kind, read at HEAD.** In the first trial of this skill (2026-11-15, a rate limiter in zukhruf), "the newest commit that added a package" picked `packages/sqlite/notify`: a nested package, named after its family by ADR 0002, as the template for a top-level one. The right template was `packages/pipes`, the newest top-level public base package. That package had also changed since the commit that added it, so the template's files are read at HEAD.

**The lockfile, the root reference and the group version ride the first commit.** On 2026-10-28 d7f1e56 added @zukhruf/sqlite-reader with neither lockfile entries nor a root tsconfig reference. Any peer push would have turned `npm ci` and `nx sync:check` red for everyone. The same day a new package copied from a sibling started at 0.3.46 while the fixed release group was at 0.3.52. `experiments-mutex/new-package-commit-needs-lock-and-tsconfig.md`

**npm writes the lockfile, never a hand.** On 2026-11-08 hand-deleted lockfile entries left a tree where every package existed and some had the wrong version: Ambient died with ERR_MODULE_NOT_FOUND, then htmlparser2 loaded the wrong `entities`. Restore from HEAD and let `npm install` rebuild it. `experiments-context-compiler/lockfile-through-npm-not-by-hand.md`

**The source condition is `@<scope>/source`.** _"I do not like the name. the ts community must have picked proper generic name"_, on a bare `zukhruf` condition. Nx's docs and Colin McDonnell's "live types" use `@<scope>/source`. Vite 8 sets `development` for every consumer, and Nx 21.5 moved away from it. Tests stay on `dist`: _"test target should have build target as depends on"_ (2026-10-08). `experiments-mutex/source-condition-not-packed-checks.md`

**A private package takes its workspace siblings as `"*"`.** On 2026-10-30 a caret `^0.4.0` stopped matching after the group's minor bump. npm locked a registry copy, imports resolved to it, and `nx sync:check` went red in CI (c41271f). `experiments-mutex/private-packages-take-workspace-star.md`

**Take the latest stable version.** _"keep going. use latest packages"_ (2026-10-06); _"update to latest typescript and update any package to latest when needed"_ (2026-10-10). Read `npm view <pkg> dist-tags` and declare `^<latest>`. `experiments-elt/use-latest-packages.md`

**Under legacy-peer-deps, a needed peer is a dependency.** Ezz's `~/.npmrc` sets `legacy-peer-deps=true`, so consumers on this machine install no peers. On 2026-10-15 a Vite consumer of @zukhruf/shadcn failed on `react-is`, a peer of recharts; the package now lists it as its own dependency. `experiments-mutex/user-npmrc-legacy-peer-deps.md`

**No engines, LTS aliases only.** _"use lts as node version not numbers. always lts"_ (2026-10-07); _"everything lts no exception"_ (2026-10-29). `engines.node` ranges were dropped: a range that nothing tests is a claim the packages cannot keep. `experiments-mutex/node-versions-are-lts-aliases.md`

**Never run nx sync in a shared tree.** On 2026-10-28 a peer's uncommitted package left the workspace out of sync, and `nx sync` would have written the peer's root tsconfig. Run targets with `--skip-sync` instead. The pre-commit hook's Sync step still staged peer tsconfig changes into commits on 2026-11-07, 2026-11-08 and twice on 2026-11-14. Run `nx sync:check` right before each commit, and read `git show --stat HEAD` after it. Tell peers at once about a new package folder, because its reference lands in whoever commits next. `experiments-mutex/nx-skip-sync-for-peer-drift.md`, `experiments-mutex/pre-commit-hook-sweeps-peer-files.md`

**Read the inferred targets; share repeated ones.** On 2026-07-28 an agent read a project.json, claimed the frontend had no typecheck target, and filed a false gap; the Vite plugin infers it. `nx show project <name> --json` lists every target. For a third copy of the test command: _"learn from deepagents how they configure test target in nx.json to avoid replicating everywhere"_. `January-text2sql/reference-nx-inferred-targets-not-in-project-json.md`, `experiments-mutex/shared-targets-in-nx-json.md`

## Conflicts and how they were settled

**When to extract: strike 3 or two consumers.** `~/.claude/CLAUDE.md` says strike 3, counted by places, and byte-identical copies wait too (the user's choice, 2026-10-09). Three memories say two is enough. In text2sql, Ezz asked _"is that not in a shared package where you can just use it again?"_ about two copies (2026-06-12) and built the shared primitive himself (`January-text2sql/feedback_consolidate_duplicate_ui_into_stdlib.md`). In virtual-care, after an agent said it would extract at a third file, the memory records the correction: within an app the threshold is 2 (`mo-virtual-care/feedback_extract_at_two_consumers.md`). And _"it is generic. that is why I told you about my freidn and startup credit. it is just 2 consimers"_ (2026-11-03, `experiments-context-compiler/two-consumers-mean-generic-home.md`). The skill follows CLAUDE.md, because it is Ezz's standing instruction and names the 2026-10-09 choice. The one exception is a domain-free package that Ezz calls stdlib and wants on npm: it moves at strike one (`experiments-mutex/publishing-moves-stdlib-at-strike-one.md`). My reading: the 2026-11-03 case was a capability Ezz asked for by name, which fits that exception better than a count of copies.

**Who shapes the API: consumer call sites or the domain.** On 2026-10-07 Ezz asked _"where are we using this today in our repo. I need to justify the addition."_ and on 2026-10-11 _"please check all zukurf packages"_ (`experiments-context-compiler/zukhruf-packages-justified-by-consumers.md`). From 2026-10-20 on he ruled the other way: _"this new package drive the other repos not the otherwise"_, and a capability goes in or out for a domain reason, never for "no consumer yet" (`experiments-mutex/stdlib-package-drives-consumers.md`, last reaffirmed 2026-11-15). On 2026-11-13 and 2026-11-14 he added that the size of the work never decides (`experiments-mutex/effort-is-not-a-design-reason.md`). The skill follows the later rulings: design from the domain, and treat call sites as evidence. The older memory survives in two places: the inventory of real callers, and naming only callers that exist.

**Decide or ask.** `experiments-mutex/decide-correct-design-not-preference.md` says: decide where the leaders agree, and ask only where they split and a caller sees the difference (2026-11-13, reaffirmed 2026-11-15). `mo-virtual-care/feedback_discuss_design_space_first.md` says to list four to six alternatives and wait for the user before any edit. `experiments-context-compiler/no-api-design-change-without-asking.md` says _"Don't change any API design without talking to me first."_ (2026-11-13). A leaders table replaces the list of four to six options.

**Export condition: `@<scope>/source` or `development`.** `experiments-mutex/source-condition-not-packed-checks.md` (2026-10-08) names the condition `@<scope>/source`: Vite 8 sets `development` for every consumer, and Nx 21.5 moved away from it. text2sql's dev apps bundle libraries through `development` (2026-09-23, `January-text2sql/reference-esbuild-watch-failure-deletes-output.md`). The skill follows `@<scope>/source`: it is the newer ruling, and the leak shows why a scoped name is needed.

**nx sync.** `experiments-mutex/nx-skip-sync-for-peer-drift.md` (2026-10-28) says never run `nx sync` in the shared tree; use `--skip-sync`. text2sql's scaffold note says run `nx sync` after a new package (`January-text2sql/feedback_new_primitive_own_stdlib_package.md`, no date). elt's commit note says that when `sync:check` fails, run `nx sync` first (2026-11-02, `experiments-elt/commit-with-pathspec.md`). **Naming: take the precedent's name, or offer Ezz a choice.** `experiments-mutex/industry-terms-not-coined.md` says take the name of the matching Go or .NET package (2026-11-14), or the industry term, with a source. `January-deepagents/feedback_naming_avoid_ingredients.md` (no date) says, when proposing a composable API, pick two or three alternatives and let the user choose. **Golden values, or the best behavior.** `experiments-mutex/package-swaps-need-blackbox-regression-tests.md` says the black-box test passes unchanged after the swap. `experiments-mutex/best-design-not-current-behavior.md` says to implement the best behavior and never keep today's quirks. The skill keeps both. The golden test catches each change that nobody planned. A quirk that the swap fixes on purpose changes its golden value in the swap commit, and the change is named to the user.
